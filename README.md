## 🚀 featured builds

<details>
<summary><b>🧞 PrepGenie</b> — agentic AI career coaching platform</summary>

<br/>

Parses a candidate's resume + target role, generates a personalized competency map, runs multi-turn mock interviews, and returns structured, evidence-backed feedback — not generic advice.

| | |
| :-- | :-- |
| **stack** | FastAPI · Next.js 14 · TypeScript · Supabase (Postgres + Auth + RLS) · Gemini API · Tailwind CSS |
| **scale** | multi-tenant sessions, persisted transcripts, async jobs for long-running generations |
| **perf** | streamed tokens for sub-second perceived latency; cached embedding + prompt layers |
| **security** | RLS on every tenant table, server-side key custody, schema-validated output, rate-limited endpoints |
| **impact** | built & shipped for the HACK AI hackathon |
| **repo** | [view →](https://github.com/shubh4m03) |

> The hard part wasn't calling a model — it was making a non-deterministic system behave like a product. Every agent response is constrained to a typed schema, validated at the boundary, and rejected-and-retried on contract violation. The LLM is treated as an unreliable dependency: budgeted, timed out, and always paired with a deterministic fallback.

</details>

<details>
<summary><b>📍 ShiftPin</b> — enterprise staff attendance & workforce tracker (PWA)</summary>

<br/>

Production PWA for workforce attendance at Raj Laxmi Enterprises — built for low-end Android devices on flaky networks. Installable, offline-tolerant, and resistant to proxy punch-ins.

| | |
| :-- | :-- |
| **stack** | React · TypeScript · Supabase (Postgres + Auth + Realtime) · Service Workers · Tailwind CSS · PWA Manifest |
| **scale** | multi-role admin/staff tiers, realtime attendance state, auditable history |
| **perf** | app-shell caching + offline queueing — punches survive network loss and reconcile on reconnect |
| **security** | admin-only provisioning, device binding vs. shared credentials, RLS isolation, immutable audit trail |
| **impact** | replaced paper registers with a verifiable digital system for a live business |
| **repo** | [view →](https://github.com/shubh4m03) |

> Integrity over features. Attendance systems fail when one person can punch in for another — so each account is bound to a registered device and provisioning flows exclusively through the admin tier. Offline-first was mandatory: events queue locally and reconcile server-side with conflict rules.

</details>

<details>
<summary><b>🐦‍⬛ RAVEN-Recon</b> — terminal-native reconnaissance aggregator</summary>

<br/>

TUI-first recon orchestration that drives an industry-standard toolchain end to end and normalizes everything into one queryable dataset. No browser, no GUI — just the terminal.

| | |
| :-- | :-- |
| **stack** | Python · Textual (TUI) · asyncio · subfinder · httpx · naabu · nuclei · SQLite |
| **scale** | concurrent subdomain enum, probing, port scanning, and template scanning across large scopes |
| **perf** | async orchestration, bounded worker pools, rate control, incremental streaming to the UI |
| **security** | scope-enforcement guardrails, engagement-bound target validation, local-only storage, zero telemetry |
| **impact** | collapses a fragmented manual workflow into one reproducible pipeline for pentest & red team work |
| **repo** | [view →](https://github.com/shubh4m03) |

> Recon is usually a pile of shell history and mismatched output formats. This treats it as a data pipeline: every stage emits normalized records, later stages consume upstream output automatically, and out-of-scope targets are rejected **before any packet leaves the host**.

</details>

<details>
<summary><b>🌌 SG-Portfolio</b> — high-performance static engineering portfolio</summary>

<br/>

Zero-runtime-JS portfolio on a content-driven static architecture, tuned for near-perfect Lighthouse scores and instant first paint on slow networks.

| | |
| :-- | :-- |
| **stack** | Astro · TypeScript · Tailwind CSS · GitHub Actions · GitHub Pages |
| **scale** | fully static, content-collection driven, CDN-backed |
| **perf** | island hydration with zero client JS by default, pre-rendered routes, optimized assets |
| **security** | no server surface, no trackers, CI-only deploy path |
| **impact** | demonstrates performance engineering by *being* the artifact |
| **repo** | [view →](https://github.com/shubh4m03/SG-Portfolio) |

> Every dependency had to justify its bytes. Content lives in typed collections so the build fails on malformed data instead of shipping a broken page.

</details>

<details>
<summary><b>🍜 Kitchenette</b> — campus food ordering SPA</summary>

<br/>

Three-role (customer · vendor · admin) campus food ordering SPA with the full order lifecycle, client-persisted state, and a deterministic state machine.

| | |
| :-- | :-- |
| **stack** | JavaScript · HTML5 · CSS3 · LocalStorage · component-based SPA architecture |
| **scale** | three role surfaces sharing one normalized client-side data layer |
| **perf** | instant route transitions, no network round trips, O(1) reads from an indexed store |
| **security** | role-scoped view gating, validated state transitions, defensive handling of corrupted state |
| **impact** | a complete multi-role commerce workflow with zero backend |
| **repo** | [view →](https://github.com/shubh4m03) |

> No backend forced the design work into the data layer: invalid order transitions are rejected, not silently applied, and persistence is versioned so a schema change never bricks a returning user.

</details>
